---
name: 材料缺口分析
description: 基于知识库生成内容前，先校验材料是否充足；不足则列出缺口而非硬凑
---

## 什么时候用它

用户要求你基于知识库/已有材料生成一份特定主题的内容（汇报、总结、方案、邮件等），而你不确定知识库是否包含足够的支撑信息时。**不要直接动笔**，先执行本流程。

## 按什么步骤做

1. **拆解题目，提取必要信息要素**
   - 问自己：要把目标输出立起来，至少需要哪些信息？
   - 按目标输出的体裁列出清单。例如：
     - 给领导的项目汇报 → 项目名与目标 / 当前状态 / 支撑证据 / 需拍板的事 / 代价或风险
     - 技术方案评审 → 问题定义 / 备选方案 / 评估维度 / 推荐及理由
     - 数据分析报告 → 数据范围 / 关键发现 / 业务含义 / 行动建议

2. **逐一检查知识库**
   - 对清单中每个要素，在知识库中搜索匹配内容。
   - 标记状态：✓ 有 / ✗ 无 / ? 模糊（有但不确定是否相关）。
   - 注意区分：材料是否存在 ≠ 材料是否**相关**。无关材料即使存在也不算 ✓。

3. **判断是否达标**
   - 如果清单中所有关键要素都 ✓ → 可以继续生成正式内容。
   - 如果任一关键要素 ✗ 或 ? → **停止生成，进入第 4 步**。

4. **输出「材料缺口说明」而非硬凑内容**
   - 结构固定为三部分：
     - **结论先行**：一句话说明当前无法完成的原因（材料不足，不是能力不足）。
     - **现有材料盘点**：手上实际有什么（简要分类列举），指出它们为何不能支撑目标输出。
     - **需要补齐的要素清单**：列出具体缺什么，每项附一句「为什么需要它」。
   - 最后补一句：补齐后建议的输出格式/框架，让用户知道方向不变，只是等材料。

5. **绝对不要做的事**
   - 不要从无关材料中强行拼凑一个看似合理的答案。
   - 不要用通用模板冒充个性化结论。
   - 不要省略缺口说明直接说「请补充材料后重新提问」——用户需要知道**具体缺哪几项**，不是笼统的「请补充信息」。

## 输出示例

> **结论**：目前无法完成 [目标输出]，因为知识库中缺少 [关键要素]。
> 
> **现有材料**：[分类列举现有内容，说明不相关的原因]
> 
> **需要补齐**：
> 1. [要素1] — [为什么需要]
> 2. [要素2] — [为什么需要]
> 3. ...
> 
> 补齐后按「[框架顺序]」组织为 [输出形式]。
