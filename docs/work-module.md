## 0. 一句话

**工作模块 = 一条「处理工作」的工作流**：给一块工作（一个题目 / 一份材料）→ AI 按**固定工序**处理 → 出成品。

服务的是你 **AI 应用开发工作里除编程以外**的活〔你定的〕，就三类：

1. **调研 · 选型 · 竞品**
2. **写需求 · 方案 · 文档**
3. **汇报 · 周报 · 沟通稿**

形态：**先要一条现成的固定流程**〔你定的〕——装好就能用，不是让你去搭积木。
节奏：**分步走，每步可停**〔你定的〕——跑完一步停下来给你看 / 改，点了（通过 / 退回）再下一步。

## 1. 现状：差在哪〔码〕

- `/work` 是**只读面板**（`routers/work.py` 自写「只读、不落库、不写盘」），列工作流 / 会议 / 产出。
- 那里的「工作流」= **定时任务**（到点跑一个提示词 / 一个引擎）〔码〕——不是「处理**一件工作**」的流程。
- 能复用的料都在手上，**不用新造生成能力**〔码〕：
  - 五个成文引擎：`research`（调研）/ `decide`（方案）/ `compose`（成文）/ `conflict`（对质）/ `recap`（复盘）——§15 起已能无人值守跑。
  - `deliver`：体裁 × 读者的交付（周报 / 汇报 / 短稿…）。
  - 「一件事」的材料与挂接（`threads.deliver_into` 验证过「就这件事写交付」）。

**所以要做的不是新引擎，是**——**把这几步按你工作的形状固定成一条流程，在工作模块里跑起来。**

---

## 2. 这条工作流长什么样

**进料**：一个**题目**（一句话，如「要不要上向量库选型」「AI 客服一期需求」）；可选钉 1–2 份你自己的材料。

**固定工序**（都用现有引擎，产物各落它该在的目录——§15 已定）：

| 步 | 用什么 | 干什么 | 落点 |
|---|---|---|---|
| **1 调研** | `research` | 拿题目去查：你自己的库 + 联网，带引用成文 | `vault/research/` |
| **2 方案 / 文档** | `decide` → `compose` | 基于调研给出选项 / 标准 / 权衡 / 结论，整理成能交出去的成文 | `vault/decisions/`、`vault/notes/` |
| **3 汇报 / 沟通稿** | `deliver` | 面向读者（leader / 团队）的成品：周报 / 汇报 / 短稿 | `vault/deliver/` |

- **竞品对质**是可选的旁支〔判〕：题目是「竞品对比」时，第 1 步后插一次 `conflict`（查说法互相矛盾处），落 `conflicts/`。
- **产物在哪看**：这四份同屏汇总——复用 `/work` 的产出清单 + 把它们挂到同一条「一件事」上，好一眼看完。

**可复用**：这条流程存成一条 **preset**（像现有的「会议闭环」`install_meeting_preset` 那样一键装），下次换个题目再跑。

### 2.1 「每步可停」不用新造机器〔码〕

`ScheduledTask.require_approval`（**人工卡点**，`core/tasks.py::review_gate`）本来就是
「这一步跑完**停下**，等人点头才交给下游」，`/work` 上已有**通过 / 驳回**的按钮。
所以这条工作流就是**一条三步、每步带卡点的链**——和现成的「会议闭环」`install_meeting_preset`
**一个模子**。M1 基本上是**照会议 preset 再造一条工作 preset**：不碰核心，只在 preset 里
把三步的 `action` / 提示词 / `require_approval` 配好。

- 第 1 步用「题目」起链（手动触发：你输入题目 → 起链）；第 2、3 步 `trigger_kind="chain"`，靠上游交接触发。
- 每步 `require_approval=True` → 跑完停在「等你点头」；你**通过** → 下一步接手，**驳回** → 流程到此为止（这一步的产出留着）。

> ⚠️ **一个要落实的点**：链里每步的提示词是**固定**的，而第 1 步要有**你当场输入的题目**。
> 做法 M1 里定，两种都不大：起链时把第 1 步的 `prompt` 设成题目（写库再跑），或给 `run_task` 加一个
> `topic` 覆盖参数。第 2、3 步靠链的 handoff 拿上游产出，不用改。

## 3. 在工作模块里怎么用〔判〕

- `/work` 顶部加一个 **「处理一项工作」**：输入题目 → 跑 → 三步产物**逐步出现**（SSE 流式，像现有交付生成那样）。
- 产物落进下面已有的**产出**区；也可选挂到一条「一件事」。
- 想让它按时跑（如「每周一出一份进展汇报」）：把这条流程交给**现有的定时任务**（§15 已能让引擎上调度），不新造调度。

---

## 4. 和已有东西的关系（不推倒重来）〔判〕

- **不新造生成能力**：三步全是现有引擎；这条流程只是**把它们按你工作的形状串起来**。
- **不新造调度**：要定期跑就挂到 `ScheduledTask`。
- **不新造归档**：产物进现有 vault 目录 + 产出清单；要归拢就挂「一件事」。

**明确不做**：卡片 / 看板 / 多人协作 / 外部系统（邮件·Slack）接入 / AI 自主抢单 / 任何「还欠 N」的债感文案。

---

## 5. 分步落地

- **M1（根）**：照「会议闭环」再造一条 **工作 preset**（三步链，每步 `require_approval`）——`/work` 上多一个「处理一项工作」入口：输入题目 → 起链 → 每步跑完停下，你**通过 / 退回**。**只碰工作模块。** → **已完成，见 §7**。
- **M2**：产物挂到一条「一件事」；preset 可一键装 / 复用。 → **已完成，见 §8**。
- **M3（可选）**：竞品对质旁支；或把这条流程接到定时任务上按期跑（§15 已能让引擎上调度）。 → **暂缓（你定的）**，理由见 §9。

## 9. 为什么 M3 暂缓（2026-09-16 定的）

两件都**没有技术障碍**，暂缓是价值判断，把它记下来免得下次重新推一遍：

1. **竞品对质旁支**：`conflict` 引擎已经能单独跑（学模块的即开工具里也有），而这条链**仍然要你手动起**——低频的话它只是把链变长，多一次放行、多一次调用，换一份「矛盾清单」。真要做，前提是「比较型题目」在你手里是高频的。
2. **按期跑**：技术上比想的便宜——第一步的题目走 `run_task(topic=…)` 运行期覆盖，**定时跑时题就从任务行的 `prompt` 里来**，那条路本来就通（M1 里那句「模板占位」正好就是它缺的那半）。真正的代价不在实现，在**语义**：按期跑会**累积**（同一个题目每周一份调研叠在同一件「事」上），要么配一个「跑完归档旧的」，要么接受那件事变成流水账。

**另一条不想瞒着的前提**：如果你要的只是「每周一份进展汇报」，**现在就有更短的入口**——在某件「事」上直接写交付（`deliver` 引擎，体裁选周报），或让 `recap` 每天自动复盘。M3b 的价值只在「**确实想要那条三步链自己跑**（带卡点、逐级交接）」时才成立。

> 决定：**先手工用几天**（起几个题目），看缺的是哪一块再回来定；届时如果只是嫌手动，那要做的可能是「一键重跑上次的题目」，而不是接调度。

> **实测补记（2026-09-23）：那句话兑现成一次读数——工作链一次都没跑过。**
> 库里 `tasks` 一共 **2 条**，都是 S1 技能验证那条 `compose` 任务（`trigger=cron`、`enabled=False`），
> `task_runs` 一共 **2 行**、都在 2026-09-17；**没有任何 `trigger_kind='chain'` 的工作 preset 行**。
> 所以 §9 那两个前提（「比较型题目高频」「想让那条三步链自己跑」）今天**都没有依据**——
> M3 继续暂缓，**这不是"没做"，是它的前提还没出现**。
> **下次再问「要不要做 M3」**：先看 `/work` 的运行记录那栏（或一条 SQL：`tasks` 里有没有
> `trigger_kind='chain'` 的行），别从零再推一遍；有了真实使用量再回来定那两件，届时
> 「按期跑」还要顺手定它的**语义**（累积 → 配一个"跑完归档旧的"，还是接受那件事变流水账）。

**你要的汇报稿不该落进 `tasks/` 堆里**（那儿是运行留痕，没人会去翻）。M2 的挂接直接建立在这条上（§8）。

## 8. 实施记录 · M2（已完成）

**一句话**：题目就是这件事的名字 —— 起链时按题目**复用或新建**一条「一件事」，
然后**三步的成品自动挂到它上面**，不用你手动点一次「挂到…」。

### 挂到哪，怎么判（这一次真正要定的事）

| 问题 | 定下来的做法 | 为什么 |
|---|---|---|
| 名字从哪来 | **你输入的题目**（`RunIn.thread`）；同名复用、没有就建一条 | 「一件事」的地基原则是**能完全不手打标签**（§4-15）。题目本来就该是这件事的名字，另起一个名字等于让你为同一件工作起两次名 |
| 怎么算同名 | 复用 `_matches`（子串包含，不猜语义）——`RAG 评测` 与 `RAG 评测的坑` 是同一件事 | 与「建议挂接」那把尺子**同一把**。归档过的事不捡回来 |
| 哪些产物算成品 | 只挂**产出目录**里的（`research` / `decisions` / `conflicts` / `recap` / `deliver`，`core.threads.PRODUCT_DIRS`） | `tasks/` 是「这条流程跑过」的留痕，`tasks/handoff/*.md` 更是中间的工序。混进「这件事」里，看的人就分不清哪些是成品 |
| 挂接失败怎么办 | 安静地不挂（**不**让一次成功的运行变成失败） | 与 `_distill` / `_score_run` 同一条纪律：顺手做的事不能变成新的失败源 |
| 判据写在哪 | 目录判据在 `threads.attach_output`；「这一步落没落盘」在 `run_task` | 两边各管一件事，不重复也不打架。**不**在 tasks 里再养一份「什么算成品」 |

### 实现里撞出来的三件事（都不是拍脑袋）

**一、挂接的判据漏了第一步。** 第一版的门是「落点目录非空才挂」——而第一步是**引擎**步：
引擎自己落盘、任务行的 `landing_dir` 是空的，于是三步里最要紧的调研产物**一份都没挂**。
根子在于：`landing_dir` 说的是「提示词步把正文写哪」，和「这一步的产物是什么」不是一回事。
改成「这一步真的落了盘就交给 `attach_output` 判」，两边各归各。

**二、过卡点会把「这件事」弄丢。** 续跑时我从**任务行**上读 `thread_id`——而任务行那个是
「这条流程最近一次在忙哪件」，链条上真正的那件是**上游传下来的**。实测症状很好认：
三步落了三个文件，只有第一份挂上了（第三份是在第二次放行时丢的）。
修法是把「是哪件」记进**那一轮运行**（`task_runs.thread_id`，v5），续跑读它。
——教训与 `run_dir` 一模一样：**停在卡点上的一轮，凡是「这一趟」的信息都得落在 run 上**，
那正是 `run_dir` 当初为什么要加的理由。

**三、`thread_id` 不在测试的清理名单里。** 工作链会建一条「事」，而这件事**跨用例可见**：
后一条用例「捡到」前一条留下的同名的那件事，于是 `created` 该是 True 却成了 False。
这是测试自己串的味（`_clear()` 少清了一张表），不是产品的错 —— 但它正好说明
**新加一张会被写的表，就要同时想清楚「谁负责收」**。

真链条那一条是端到端走的：第一步跑引擎（假引擎，**落盘不假**）→ 放行 → 第二步落 `decisions/`
→ 放行 → 第三步落 `deliver/`，结束时那件事上正好挂着三份成品，而 `vault/tasks/` 里
**一份影子副本都没有**。

### 还没做的（如实记）

- **M3 两件都没做**：竞品对质旁支（`conflict` 引擎在，但三步链里没有这个分支）、按期跑（三步都是 `chain`，不注册 cron）。
- **「同一件事」是名字撞出来的，不是选的**。撞不上就新建一条 —— 题目与已有那件事名字差得多时，
  你会得到两条名字相近的事。手工合并的路是现成的（把产物挂过去 / 删掉空的那条），
  但**没有**「起链前先问一句『是不是这件事』」。要不要问，等真被绕烦了再说。
- **挂接只发生在工作链上**。别的流程（普通定时任务）要挂还是手动点 —— 这不是漏做：
  它们没有「一个题目」这个天然的名字来源。
  **（2026-09-17 补）会议闭环现在也自动挂**：它的名字来源是落点目录——`_resolve_run_dir`
  把每一场会议落成 `meetings/<日期>-<录音名>/`，那个子目录名就是这一场会议
  （`tasks.thread_name_for_run_dir` + `threads.PRODUCT_DIRS` 里的 `meetings`）。当时写
  「它们没有天然的名字来源」是**没往下看一层**：普通定时任务确实没有，会议有。
