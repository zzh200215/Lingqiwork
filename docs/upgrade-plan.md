# 升级优化方案：把「期望行为」变成可回归的工程资产

> 作者视角：资深 LLM 应用工程 / 架构。所有诊断都带本仓库实测数据，样本量和置信度如实标注。
> 估算为**人日量级**，不是承诺。

---

## 1. 一句话结论

这个仓库的**成文引擎**（research / compose / recap / decide / conflict / deliver）和 **RAG**
两条路已经有完整的三层闭环：自动判分 + 提示词指纹 + 人工满意率，三者共用 `prompt_sha`
（`core/engine_eval.py`、`core/evals.py`、`core/quality.py`、`core/usage_ledger.py`）。

**但用户每天真正在用的那条路——聊天的工具循环——一层都没盖。**

本轮全部缺陷都出在这条路上，而且**全是靠一次性脚本量的，量完就散**：不落盘、谎报落盘、
一轮存 4 份、编造约束、编造文件路径、token 抖动 2.2×。这不是「模型不够聪明」，
是**这条路没有验收标准**。

所以这个项目的主轴不是"加功能"，是**把行为变成资产**：
把「一轮应该发生什么」写成可回归的用例，再把容易错的地方从**提示词承诺**搬到**结构保证**。

## 2. 诊断

### 2.1 已有的（不要重造）

| 资产 | 位置 | 覆盖什么 |
|---|---|---|
| 引擎质量标尺 | `core/engine_eval.py` + `backend/evals/engines/*.json` | 5 个成文引擎：结构判分（确定性、零成本）+ 接地判分（LLM 0-5） |
| RAG 评测 | `core/evals.py` | Hit@k / MRR（客观）+ 忠实度判分；记录检索配置 |
| 人工满意率 | `core/quality.py` + `ArtifactFeedback` | 按 `(kind, prompt_sha, model_id)` 聚合 |
| 用量账本 | `core/usage_ledger.py` | contextvar span，横切记账，不用改二十个模块的签名 |
| 提示词登记 | `core/prompts.py::_SPECS` | 31 条，sha 指纹，改了测试就红 |
| CI | `.github/workflows/ci.yml` | 每文件一进程跑测试 + pyflakes + tsc + vitest |

**三个可复用的缝**（方案要挂在这上面，不要另起一套）：
1. `prompt_sha` 这把 join key —— 自动分和人点的满意率落在同一把 key 上。
2. `usage_ledger.span(kind, ref)` —— 横切记账已有机制，加一条 span 即可。
3. golden set 用 JSON 文件放 `backend/evals/` —— 跟代码同版本演进，不进库。

### 2.2 缺的（本项目的靶子）

**缺口一：聊天工具循环没有任何自动判分。**
`engine_eval` 盖的是"一次生成一份成文"，`evals` 盖的是"检索准不准"。
**"模型有没有真的把东西存下来、有没有说谎、一轮存了几份"——零覆盖。**

**缺口二：回合级的可观测性为零。**
界面上能看到调了哪些工具，但**不落任何记录**：没有 tool call 的耗时/参数大小/结果大小，
没有轮数、没有路由决策、没有"这一轮为什么没存"。本轮为了量一件事，我临时写了
`.tmp-dup/measure.py` + 一个 Playwright 脚本 —— 这本身就是证据。

**缺口三：易错判断全押在提示词上。**
- 「成篇成品要存」从工具描述搬到 system：**0/10 → 6/10**（n=10，方向明确）
- 但**还没解决**：22 轮里 2 轮声称存了却一次没调（n=24，**2 vs 1 无统计意义**）
- 更糟的一种：编了一个**不存在的文件路径** `recap/2026-09-14-本周周报-精简版.md`
- 还编过**不存在的约束**：「标题字数超限（12 字 > 10 字）」——代码里没有任何标题长度限制

**缺口四：长度约束靠模型自己数数，于是它写一版存一版。**
- 提示带「300 字左右」：20 轮里 **5 轮 save ≥2 次，最坏 4 次**
- 把「300 字左右」去掉：**10/10 轮只存一次**
- 也就是说：**重复落盘不是模型的随机毛病，是字数要求逼出来的**
- 存储层已修（同轮同体裁只留最后一份：改后 16 组全部 1 文件），但**循环本身还在烧 token**

**缺口五：遵守率强烈依赖上下文，而这一点没被量化。**
同一句自然说法：vault **空**时 0/4（模型正确地拒绝编造），vault **有素材**时 15/16。
任何"遵守率 X%"的说法都必须带上下文条件，否则就是误导。

**缺口六：工程底座两处脆弱。**
- **迁移**：`main.py:73` 一张写死的 ALTER 列表，每次启动全表重放，**没有版本记录、不能回滚、没有 dry-run**。
  实测：真实库到现在还没有 `artifacts_json` 这一列（只在 app 启动时才加）。
- **测试隔离**：conftest 的 sandbox 是**全进程共用**的。CI 用 `run_tests.py` **每文件一进程**
  （实测 56/56 通过，6.2 分钟），所以 CI 是绿的;但单进程 `pytest tests/` 会因为
  `test_artifacts.py` 自己的 sandbox 设得太晚而互相污染、**随收集顺序飘**。
  也就是说：**CI 的绿掩盖了一个真实的脆弱**。

## 3. 目标与非目标

**目标**
1. 聊天工具循环有自动判分，能回答「这次改动让行为变好还是变坏」，带置信区间和成本。
2. 「说了存」= 「真的存了」——这条由**结构**保证，不由模型保证。
3. 长度约束不再诱发写-存循环。
4. 每一轮为什么慢/贵/没落盘，能在界面上查，不用起脚本。
5. 迁移有版本、能 dry-run。单进程 `pytest tests/` 与 CI 结论一致。

**非目标（明确不做）**
- 不猜体裁、不自动分类产出（用户已定的原则：`compose` 落 `notes/` 不计成长值，猜错等于存了个看不见的东西）
- 不引入 LangChain / LlamaIndex / 多智能体编排框架
- 不为指标改产品语义（比如为了"落盘率"把普通回答也存成产出）
- 不追多模态 / 微调 / 自建推理

---

## 4. 架构主线：三处「从提示词搬到结构」

| | 现在 | 目标 |
|---|---|---|
| **交付物** | 模型"记得的话"就调 `save_artifact`，忘了/说谎了没人拦 | 交付物是**回合契约**的一部分：没真落盘就没有回执，回执由服务端生成 |
| **路由** | 指望模型自己判断"这是要成品" | 生成**之前**定路由，决策可回放、可评测 |
| **长度** | 模型自己数、自己重写 | 长度是**后置条件**，由服务端裁剪或单次受限修订 |

## 5. 工作流

### W1. 聊天工具循环的行为评测（keystone）

**问题**：缺口一。所有改动都是手感，2/24 vs 1/24 分不出真假。

**做法**
- 新增 `core/turn_eval.py` + golden set `backend/evals/turns/*.json`（跟 `evals/engines/` 同一约定）。
- **判分器分两层，和 `engine_eval` 保持一致的分工**：

  | 判分器 | 类型 | 断言什么 |
  |---|---|---|
  | `saved_at_least_one` | 确定性 | 该落盘的轮真的落了盘 |
  | `claim_is_truthful` | 确定性 | 声称存了就必须有回执（复用已落地的 `chat.claims_a_save_without_one`） |
  | `one_artifact_per_kind` | 确定性 | 一轮同体裁 ≤1 份 |
  | `no_duplicate_paths` | 确定性 | 回执路径不重复 |
  | `body_not_in_reply` | 确定性 | 落盘那一轮的正文没有同时摊在回复里 |
  | `receipt_is_one_line` | LLM judge | 回复是"一行回执"而不是把成品复述一遍 |

- **落库形态**照抄 `EngineEvalRun`：新建 `TurnEvalRun(id, created_at, scenario_sha, prompt_sha, model_id, total, deterministic_pass, judge_score, seconds, detail_json)`。
  `prompt_sha` 用**和 `_OUTPUT_RULE` 同一个算法**，于是自动分和 `ArtifactFeedback` 天然可对照。
- **成本记账**：整轮套 `usage_ledger.span("turn_eval", …)`，不用新机制。
- **统计出口是硬要求**：报告必须是 `k/n` + **Wilson 置信区间**，不是裸比例。
  本轮教训：裸比例会让人把噪声当结论。
- CLI：`uv run python -m app.eval_turns --model sensenova/… --n 24 --scenario deliver_weekly`

**验收**
- 一条命令跑出「本轮改动对聊天工具行为的影响」：通过率 + 区间 + 成本 + 失败用例逐条理由。
- **把本轮发现的所有缺陷写成用例**（谎报、编路径、一轮 4 份、同轮覆盖、正文回填、占位串）——先把回归网织上，再谈优化。

**规模** 3–4 人日（判分器大多是确定性、零成本）｜**不做什么**：不做通用 agent benchmark，只测本产品承诺过的行为。

---

### W2. 交付物成为回合契约的一部分

**问题**：缺口三。「说了存」靠模型自觉，实测 2/24 说谎、还能编出不存在的路径。

**做法（两步，先便宜后彻底）**

**W2a 事后校验 + 有界修复**（1–2 人日）
- 校验器已有（`claims_a_save_without_one` + 界面警告）。
- 补两条：①**"长正文 + 无产出"**——正文超过阈值（比如 400 字）且没有回执 → 判定为"该存没存"；
  ②**回执路径白名单校验**——模型报的路径必须在本次落盘记录里，否则界面上不渲染成可点链接。
  （编造路径那条，用户现在看到的是一个可信但点开即 404 的东西，这必须堵掉。）
- 修复动作：**只重试一次**，明确告诉模型"上一轮没有落盘，这一轮必须调用"，并把重试计入 trace。
  失败就把"存进产出"按钮提到最显眼处，让用户一键补。

**W2b 强制结构化回应**（3–5 人日，按 provider 灰度）
- 对判定为"交付型"的回合，要求模型返回 `{reply, artifacts:[{kind,title,body}]}` 结构
  （走 `response_format` / 强制 tool_choice）。
- **正文由结构承载，回执由服务端生成**——模型失去"说谎"的表达空间：没有 artifacts 字段就没有回执。
- provider 不支持就回落到 W2a，**每个 provider 的能力记在 W7 的画像里**。

**验收**
- 谎报率 = **0**（确定性，不依赖模型）；golden set 上长文卡不再出现在对话里。
- 回执里的每个路径都能点开（加一条端到端断言：回执路径 → HTTP 200）。

**不做什么**：不自动猜体裁。结构化里 `kind` 由**路由**（W3）或**用户点击**决定。

---

### W3. 确定性路由：把易错判断从模型手里拿走

**问题**：缺口三的另一半。「这是要一份成品还是问一个问题」现在完全靠模型，而实测
空 vault / 有素材下表现差异巨大（0/4 vs 15/16），说明它在这件事上不稳定。

**做法**
- 三级路由，逐级回落，**每级都记决策与置信度**：
  1. **规则**：祈使动词（写/整理/出一份）+ 成品名词（周报/方案/复盘/调研）+ 长度意图 → 高置信
  2. **向量**：和金标集比对（复用现成的 `core/embedder.py` / `retriever.py`）
  3. **小模型**：便宜模型做一次二分类，带 JSON 结构输出（`core/structured.py` 已有自纠正机制）
- 路由结果决定：是否走 W2b 的强制结构、是否给 `_OUTPUT_RULE`、`kind` 的候选集。
- **可回放**：每次决策连同输入、级别、置信度写进 W5 的 trace，能被离线复算。

**验收**：金标路由集（≥60 条，正确/负例各半）上准确率 ≥ 0.9，且**负例（普通提问）零误判**——
误判的代价是把闲聊变成产出，比漏判更烦人。

**规模** 3–4 人日｜**不做什么**：不做意图体系、不做多轮槽位填充。

---

### W4. 长度约束的确定性执行

**问题**：缺口四。「300 字左右」让模型写一版存一版（5/20 轮 ≥2 次），最坏一轮 4 次，
白烧 token 还堆文件。已量到因果：去掉字数要求 → 10/10 只存一次。

**做法**
- 长度作为**后置条件**，三选一（按体裁配置）：
  1. **服务端裁剪**：确定性截到预算（适合摘要、回执类）；
  2. **单次受限修订**：模型只允许改一次，且**修订走同一个文件**（存储层已支持同轮覆盖）；
  3. **预算内生成**：把预算写进结构参数，落盘时服务端校验，超了**不接受**并回一次结构错误
     （复用 `core/structured.py` 的自纠正循环，但有硬上限）。
- `save_artifact` 增加可选 `length_budget`，并在返回值里如实报告实际字数——
  让"超没超"这件事**服务端可见**，不再靠模型的自我叙述。
- 用 W1 量：**每轮 save 次数**、**每轮落盘文件数**、**每轮 output token**。

**验收**：每轮 save 次数均值 1.25 → **≈1.0**；每轮落盘文件 ≈1；同题改动下 output token 不升。

**规模** 2–3 人日

---

### W5. 回合账本与可观测性

**问题**：缺口二。这一轮的每一个结论都是临时脚本量出来的，量完就散，下次还得重写。

**做法**
- 扩展 `usage_ledger` 的 span（不要另造机制），落一张 `turn_traces`：
  `created_at, conversation_id, message_id, model_id, prompt_sha, route_level, route_kind,
  rounds, tool_calls_json(名称/参数大小/结果大小/毫秒), tokens_in, tokens_out, cost,
  artifacts_json, claim_checked, claim_truthful, retried, seconds`
- 界面：在现有仪表盘/质量页加一栏「最近回合」，能按"没落盘 / 谎报 / 多份 / 贵 / 慢"筛。
- **红线**：这是诊断工具，不是考核仪表。不设目标、不催、不做排行榜
  （沿用 `quality.py` 已定的护栏语气）。

**验收**：「这一轮为什么慢了/贵了/没存」能在界面上点出来，**不用起脚本**。

**规模** 3–4 人日｜依赖：无（可与 W1 并行）

---

### W6. 工程底座：迁移版本化 + 测试隔离

**问题**：缺口六。

**做法**
- **迁移**：写死的 ALTER 列表 → `schema_migrations(version, name, applied_at)` + 有序迁移函数。
  启动时只跑未应用的；提供 `--dry-run`；**迁移前自动备份**（`core/backup.py` 已有能力）。
  首个迁移就是基线（把现有列记为 v1），不重写历史。
- **测试隔离**：conftest 的 sandbox 从"全进程一个"改成**每测试模块一个**
  （`tmp_path_factory` 风格，但根目录落在仓库内 —— 实测本机 `%TEMP%\pytest-of-TX` 是拒绝访问的残留目录，
  `tempfile.mkdtemp` 在系统 temp 下也会被沙箱拒）。
  目标：`pytest tests/` 单进程运行与 `run_tests.py` 结论一致。

**验收**：单进程全绿且与 CI 一致；迁移有版本记录、能 dry-run、能回滚到备份点。

**规模** 2 人日

---

### W7. 模型画像与 per-model 策略

**问题**：同一个提示词喂所有模型，但实测行为差异巨大：flash-lite 需要把规矩提到 system 层
且仍会谎报/循环;deepseek-v4-pro 限流且输出不完整;qwen 另配一套。

**做法**
- `model_profiles`：per-model 的 `temperature / tool_choice 策略 / 是否强制结构输出 /
  max_rounds / 长度处理策略 / 是否给 _OUTPUT_RULE`。
- **每个画像必须有一条 W1 跑出来的行为基线**，否则不许上线——这是本方案的核心纪律。
- 换模型 = 换画像 + 跑一遍基线，不再靠"看起来还行"。

**验收**：每个在用模型都有基线分、成本、延迟三项记录；改画像有前后对照。

**规模** 2–3 人日

## 6. 分期与里程碑

| 阶段 | 内容 | 产出（可验证） | 估算 |
|---|---|---|---|
| **P0 底座** | W6 + W5(最小版) | 单进程测试与 CI 一致；迁移有版本；回合 trace 落库 | 4–5 人日 |
| **P1 织网（keystone）** | W1 + 把本轮全部缺陷写成用例 | 一条命令给出行为回归报告（含置信区间与成本） | 4–5 人日 |
| **P2 结构修复** | W2a → W4 → W2b | 谎报 = 0；每轮 save ≈1；长文不再进对话 | 6–9 人日 |
| **P3 优化** | W3 + W7 | 路由金标 ≥0.9 负例零误判；每个模型有基线 | 5–7 人日 |

**关键顺序约束**：P1 必须在 P2 之前。没有 W1，W2/W4 的改动无法判断好坏——
这一轮已经吃过一次：把"改进了吗"这个问题用 24 个样本去问，答案是"不知道"。

## 7. 度量

**北极星**：**「用户开口要成品 → 成品真的落在 vault 且被正确回执」的成功率**
（现况：有素材时 15/16 ≈ 94%，但其中 8% 的轮次会说谎或不落盘；空 vault 时模型正确拒绝，不计入分母）

**护栏（不许变坏）**
- 谎报率 = **0**（确定性）
- 每轮 save 次数均值 ≈ 1
- 每轮 output token P95（现况波动 723–1614，2.2×）
- 每轮成本、首 token 延迟
- 负例误判率 = 0（普通提问不许被塞进产出）

**过程指标**
- 行为用例覆盖的缺陷类别数
- 提示词改动**带 A/B 证据**的比例（现在是 0，本轮所有 prompt 改动都无证据）
- 每个在用模型是否有基线

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| provider 不支持强制结构输出 | W2a 兜底 + W7 画像按 provider 灰度；不搞"一刀切" |
| 评测成本失控 | 判分器尽量确定性（零成本）；LLM judge 只用于必要项；跑评测套 `usage_ledger`，单次预算上限写进 CLI |
| 样本量不足导致假结论 | **报告强制带 Wilson 区间**；n 不足时输出"无法判定"而不是一个比例 |
| 过度工程 | 每个 W 都写了「不做什么」；W1 只测本产品承诺过的行为 |
| 结构化输出破坏现有流式体验 | W2b 只在"交付型回合"生效，普通聊天路径**一个字节都不动** |
