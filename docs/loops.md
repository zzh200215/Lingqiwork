# 三条「化学反应」环的取舍，以及先做的那一条

> 2026-09-16。起因：提案「学习 → 工作 → 宠物互相驱动」——学习反哺工作（论文 → 工作台小工具）、
> 工作反哺宠物（发零食 / 金币 → 买皮肤 / 解锁高级模板）、宠物反哺学习（宠物发现你老搞错
> 某个概念，第二天推一张复习卡并吐槽）。
>
> 这份文档记的是**取舍**（哪条做、哪条不做、为什么），不是路线图。
> 做掉的见 §3（环三）、§4/§5（环一）、§6（环二留下的那一块）；还剩什么见 §7。

---

## 1. 先说一句总的判断

三条环里：**一条是真的缺口、一条是「已经有了但没说全」、一条与仓库已经写下的规矩正面冲突。**
而它们共用同一个没被点破的问题：

> **零柒到底是镜子，还是掌柜？**

| | 镜子（现在） | 掌柜（提案的默认形态） |
|---|---|---|
| 它怎么知道事 | **读同一份真值**，算出来 | 被通知、记在**自己那本账**上 |
| 谁定义「值得」 | 你的真实累计量 | 它发多少币 |
| 坏了会怎样 | 最多不说话 | **第二份真值**：账本与事实会不同步 |

仓库已经选过边，而且是写下来的：`pet_room.py` 开篇三条规矩 ——
**算出来的不是发的奖**（没有物品表、没有一次「发奖」写库、没有 hook 挂到五个模块里去）、
**只增不减**、**不欠账**（没有「还差 N 件解锁」，也没有「它饿了」）。

提案里环一和环三是「让宠物**看见更多**」；环二是「让宠物**记账**」。
**前者是护城河，后者是把护城河填了盖收费亭**——一旦有账本，「宠物说的」与「库里记的」
就成了两份东西，而这个仓库反复吃过这个亏（`turn_trace.flags`、`saveHint`、路由结论、
小屋架子 vs 工作页清单）。

## 2. 逐条

### 环三「宠物反哺学习」——做（见 §3）

**它其实已经有一半在转了**，这点提案没说全：

| 提案里的说法 | 仓库里已有的 |
|---|---|
| 宠物发现你某个概念常搞错 | 卡点清单（`tutor.stuck_points()`）、按来源错题率生成的**错题补讲**（`cards.py` 的 `_remediate_run`，而且已经会 `pet.emit("cards_remedy")`） |
| 第二天推一张复习卡 | 复习队列（SM-2，到期拉取）——**不做定时推送**，见下 |
| 用宠物语气吐槽 | `pet.compose()` 的表达层（B1：主语是「你」不是「系统」） |

真正缺的是**一个判据**：现在宠物只在「说通了」的时候开口（`_note_first_mastery`），
它**不知道「这个概念你又没走通」**。而这句话需要的字段全在库里（`tutor_sessions`），
不用新表。所以这一条是三条里唯一「零新真值、零新机制、只缺一条规则」的。

⚠️ **但它必须是事件驱动，不能是定时推送。** `cards.reschedule()` 那段话是死线：
每日提醒与每周补讲**已经被封存**，判断标准只有一条——**任何产生「欠着没做」感觉的机制
都要停**。所以这里没有队列、没有「明天推给你」、没有计数：**你刚自评完，它才开口**，
说的是一句陈述（哪个概念、试到第几次、上次卡在哪），不是一句催办。

### 环一「学习反哺工作」——做（见 §4），落点改了

提案写的是「自动生成一个**工作台小工具**供你在工作模块使用」。「工具」在这个仓库里有
四种不同形态，落哪个决定了它是真能力还是摆设：

| 落点 | 是什么 | 判断 |
|---|---|---|
| `skills/<名>/SKILL.md` | 指令包，模型按需 `skill_load` | ✅ **选它**——见 §4 |
| 提示词对照台 | 跑金标集 → `k/n` + Wilson 区间 → 通过才登记 | ✅ 但「改已登记的提示词」是源码的事，材料变不出这条 |
| MCP / 插件工具 | 真能调用的函数 | ⚠️ 要写代码、要注册、要白名单，为一次阅读付这个价不划算 |
| 跑一段生成出来的脚本 | 一次性执行 | ❌ 这个仓库最贵的是「证明它有用」，一段没人验证过的脚本就是装饰 |

**结论**：正确形态是「**材料 → 能力候选（一份 SKILL.md 草稿）→ 进 `skills/` 但不算数 →
要它算数得先量一遍**」。不是「自动长出一个工具」，也不是「自动装一堆技能」。
范围上也诚实：这是本地优先的个人工作台，不是下载站——大多数论文的核心算法**不该**
搬进来（与「不引入 LangChain / 不做微调」同一精神）。所以它是**低频、手动确认**的一条。

### 环二「工作反哺宠物」——不做（改形态）

具体坏在三处：

1. **它让宠物同时当进度条和掌柜。** 现在「你攒下了什么」是**读**出来的（产出落盘就多一件东西，
   宠物不需要被通知）；有币可赚之后，人就会去**赚币**——正是仓库拒绝的「为指标改产品语义」。
2. **「解锁高级模板」是最坏的一句。** 它把模板变成里程碑奖励，等于宣布「你现在的模板是次品」，
   而这个工作台的立场是**装好就能用**（`work-module.md` 第一句）。模板不该有等级。
3. **「购买皮肤」现在没有落点。** 宠物形象是 `frontend/public/pet/` 下的静态资源，
   道具与徽章是**算出来的**（没有物品表、没有库存）。要卖皮肤就得先造一套库存与结算——
   为一条叙事造一个账本。

**剩下能做的、也值得做的**：让宠物为你交出去的成品**说一句带性格的话**。
成长值（`EXP_OUTPUT`）、挂件（P4）、那件「事」（M2）**都已经会自己动**，缺的只是一句话。
→ 做掉了，见 §6。

## 3. 做掉的那一条：同一个概念又卡住

### 判据（纯函数，唯一出处）

`tutor.is_recurring_mistake(c, cutoff=…)`，四个条件同时成立：

| 条件 | 为什么 |
|---|---|
| `recalled ≥ 1` | 系统**接住过**他卡在哪儿，这次带着旧卡点回来了（`say()` 的召回命中）。**这是唯一不可伪造的那一半**：不是「碰过两次」，而是「上次卡的点被端到面前了，还是没过去」 |
| `verdict == "half"` | 最近一次**半懂**。说通了（got）是新起点，不是旧毛病；「没用」（useless）是教学没成，证明不了水平（与 `concepts()` 同规矩） |
| 还没到「已掌握」 | 连着两次说通就不再算数（`is_mastered`） |
| 最近一次在 7 天内 | 更早的属于记录，不是此刻该说的一句 |

**刻意不做的**：不设复习队列、不计数、不催。「试到第几次」是**陈述**（宠物本来就要说出
「第几次」才有那个味道），不是债。

### 接线（三处，都在已有的路上）

| 位置 | 干了什么 |
|---|---|
| `tutor.end()` 的 `else` 分支 | 自评不是「说通了」时看一眼判据 —— **事件驱动**：你刚自评完，它才开口 |
| `tutor.note_recurring_mistake()` | 冷却（同一概念一天只念一遍，读**已说过的话**，不另记一张表）、取次数、交给宠物说 |
| `pet.compose("repeated", …)` | 「「X」这是第 2 次了，还是没走通。上次卡在：…」——**只陈述**，不催不劝 |

### 实现里撞出来的两件事（都不是拍脑袋）

**一、`pet_events.detail` 兼着两个角色。** 「这件事叫什么」（概念 / 任务名 / 文件名）与
「这一句的补充」，历史行都塞在 `detail` 里，于是「同一个概念说过没有」**查不出来**——
第一版冷却就是这么失效的。修法是给这张表补 `name` 列（`models.PetEvent` 有说明；
这张表历史上不走迁移，`pet.emit()` 自己 `PRAGMA` 后 ALTER），cooldown 按 `name` 查。

**二、`' '`(0x20) < `'T'`(0x54)。** `pet` 写 `created_at` 用的是 `isoformat()`——分隔符是
**空格**；而「本地零点」很容易被写成带 **`T`** 的形状。拿两个字符串直接比，**同一天的行
永远被判成过期**：冷却完全失效，而且看不出问题（查询本身是对的）。现在两边都过
`_parse_pet_time()` 变成真 datetime 再比。

> 这两条都属于「查询是对的、答案是错的」那类 bug：不写下来，下次还会踩。

### 验收

| 层 | 结果 |
|---|---|
| 判据（纯函数） | 5 条：只有「接住过 + 半懂 + 没过期」算数；单次 / 已掌握 / 没用 / 过期都不算 |
| 派生查询（真行） | 3 条：两个概念里只有「接住过那个」进清单；说通两次后自己掉出去；查询挂了返回空表 |
| 那句话与冷却 | 3 条：说一次、名字与卡点都对、次数是真数出来的；同一天不念第二遍；空概念不开口 |
| 接线（真 `end()`） | 2 条：半懂且判据成立 → 宠物开口；说通了 → 一个字都不说 |
| 全量 | 后端 **75 个测试文件全绿**，前端 287 条未受影响 |

## 4. 环一：一份材料 → 一个能力包

`core/candidates.py` + `POST /api/skills/candidate` + 工作页「实验室」标签里那一栏「🧰 读成能力」。

### 做出来的形状

给它一份材料（vault 路径 / `repo:` / `dir:` / 直接粘贴），它回答两件事之一：

- **有工序** → 落一份 `skills/<名>/SKILL.md`（frontmatter 只有 `name` + `description`，
  正文是「何时用它 + 按什么步骤做」的祈使句）。落盘即被既有机制发现：进每轮对话的技能索引、
  可 `skill_load` 按需加载。
- **没工序** → `usable=false` + 一句理由（「只是一组结论」「材料太碎」）。
  **不硬凑**——凑出来的技能没人用，只是给索引添噪音。

### 四条硬规矩（都在测试里钉着）

| 规矩 | 为什么 |
|---|---|
| **不是每份材料都能出能力** | `skills/` 里多一份没人用的指令，索引里就多一条噪音；硬凑是负收益 |
| **同名不覆盖** | 停下来，把决定交给人（界面上多一个显式的「覆盖」按钮）。手改过的技能不该被一次生成悄悄盖掉 |
| **正文是工序，不是摘要** | 「这篇讲了什么」是笔记的活；这里是「下次怎么做」 |
| **落盘 ≠ 登记** | 草稿没跑过对照、没有基线，所以 `registered=False`、界面上写明「还不叫技能卡」 |

第四条与仓库既有的两条纪律同源：W7 的「没有基线的画像不生效」、Q2 的「技能卡必须有基线才展示」。

### 一处如实交代：技能包**还没有量法** → **已有，见 §5**

（历史记录，留着是因为它解释了为什么 `/api/skills/candidates` 一开始每一份都是
`registered=false`：`PromptEvalRun` / `EngineEvalRun` 量的是登记过的提示词与引擎，
技能包（instruction pack）没有对应的一轮评测。**硬塞一个分数比空着更坏**——
那会让人以为它量过。§5 就是补这一格。）

## 5. 环一收口：技能包的量法

`core/skill_eval.py` + `/api/skills/<名>/cases|run` + 工作页那一栏里的「量一遍」。

### 它量的是什么

**有它 / 没它，同一套用例跑一遍。** 每条用例问两次（同一句话、同一模型，只少了那份工序），
然后：

| 数 | 是什么 |
|---|---|
| `with_passed / total` | 有它那一侧过了几条（`not_a_wall_of_text` 那条与工序无关的断言） |
| **`deltas.helped / hurt / same`** | **有它比没它多过了几条 / 少过了几条** —— 「有没有用」的直接答案 |
| `follows_method` | 「跟着这套工序做了没有」的 LLM 判分均值 0-5（**只判有它那一侧**，没它那侧没有工序可跟） |
| `tell` | 这次下不下得了结论（区间宽 ≤ 0.34 且用例 ≥ 3），与 Q1 同一把尺子 |

单看通过率会把「这条用例本来就简单」读成「技能有用」，所以**逐条差才是主指标**。

### 五条硬规矩

| 规矩 | 为什么 |
|---|---|
| **没有用例就没有量** | 用例是尺子。模型自己出题自己考，考的是它会不会出题 —— 所以**不自动生成用例** |
| **不复用 `prompt_eval.CHECKS`** | 那张表每条断言的 `why` 都指着**某条提示词的一句话**；搬过来量的就是别的东西 |
| **`tell=false` 时不许下结论** | n=8 全过也只有 [0.68, 1.00]；区间太宽就如实说，不给一个好看的比例 |
| **内容改过 → 旧成绩作废** | `skill_sha` 对不上 = `stale`（与 Q1 技能卡的 `stale` 同义）：那不是现在这版的成绩 |
| **判分没跑成 ≠ 0 分** | `follows_method` 用 `-1` 表示「没判」，界面上显示「判分没跑成」——0 分是量出来的结论，两件事不能混 |

### 成本（写在报告里）

`calls = 用例数 × 2 + 有它那一侧的判分次数`。4 条用例 = 8 次生成 + 4 次判分 = 12 次调用，
界面上按钮的 tooltip 与报告里都写着这个数。

### 用例从哪来（**不自动生成**）

尺子得由人给：模型自己出题自己考，考的是它会不会出题。所以界面上就是一个小表单——
每条用例两栏：

| 栏 | 是什么 |
|---|---|
| **它会收到什么**（`ask`） | 真会问它的那句话 |
| **它当时应该怎样**（`intent`） | 这条用例凭什么在集合里（与 `prompt_eval.add_case` 同一道门槛） |
| 断言（可勾选） | 不勾就用默认那条；勾了就是这条用例必须满足的 |

断言名**不认识就照样存**，跑的时候判失败并标「未知断言」——比在这里悄悄删掉它诚实。
文件落在 `backend/evals/skills/<技能名>.json`：进 git、可审、可回滚（与提示词那套同一个规范格式）。

### 验收

| 层 | 结果 |
|---|---|
| 后端 `test_skill_eval.py`（新，17 条） | 每条用例问两次且「有它」按消息里有没有 system 判定、helped/hurt 都算对（hurt 不许藏）、一次生成失败只算一条用例失败、判分只判有它那侧、判分挂了不编 0 分、没有用例 = 没有尺子、用例太少 `tell=false` 并说差几条、落库与读回、**改一行正文 → 旧成绩变 stale**、**未知断言判失败不静默忽略**（第一版调错表就是这个坑）、用例文件规范格式与坏文件容错、`cases_payload` 给的默认断言就是跑分真正用的那条 |
| 前端 `WorkPage.test.tsx`（+4 条） | 量过的摊出「过了 3/4 · 有它多过 2 条 / 少过 0 条 · 跟着工序做 4/5」；点「量一遍」出报告并写明花了多少次调用；`tell=false` 时界面上写着「这个 n 下不了结论」；**写用例**：空 `ask` 不许存、勾选状态跟着用例走、存完给一句实话 |
| 迁移 | 真库副本上 v1→v6 全跑通（`skill_eval_runs` 就位） |
| 全量 | 后端 **76 个文件全绿**（3.9 分钟，`run_tests_fast.py`）；前端 **295 条**全绿 |

## 6. 环二留下来的那一块：成品落盘 → 一句带性格的话

`pet.note_output()` + 三处写盘的人。**没有币、没有零食、没有库存、没有模板分级**——
§2 拒掉的那些一条都没进来。

### 谁说，以及为什么不是 `run_task`

| 谁写盘 | 在哪说 |
|---|---|
| 六个成文引擎（研究 / 成文 / 复盘 / 方案 / 对质 / 交付） | `report.save` |
| 定时任务的正文落 `landing_dir` | `tasks._write_vault` |
| 会话里存成产出（模型自觉调的 / 工作页那个手工出口） | `mcp._save_artifact` |

「刚刚多了一份什么」只有写的人知道，所以话由**写盘的那一处**说。判据只有一句
`pet.is_output_path`——与成长值、小屋架子、工作页产出清单、M2 的自动挂接**同一份目录清单**，
这里不另立一条（这个仓库为「同一个词指两批文件」付过太多次账）。

代价写在明处：`tasks.run_task` 因此**让位**——落了成品就不再说「跑完了」，**一件事一句话**。
不这么做的话，气泡里会同时出现两条讲同一件事的话，而「跑完了」比「交出去了」少说了最要紧的
那半句。落点不是成品（`tasks/` 的留痕）时那句话照旧，所以它不是被统一掐掉，是换了一句更准的。

### 台词

> 「周报」交出去了。这是第 3 份。

- **主语是「你」**（B1）：不是「系统生成了」；
- **数字是读出来的**（`_count_outputs()`：架子上真有几份），不是宠物记的账、更不是它发的奖
  ——「算出来的不是发的奖」从 `pet_room` 开篇一直管到这里；
- **数不出来就只留前半句**（`count == 0`）：宁可少说一句，也不编一个数。

一句如实交代：同一天同一标题再跑一遍，引擎是**覆盖**同名文件的，架子上并不会多一份——
而那句里的数照旧是架子上**真实**的份数。所以它从不说「又多了一份」（那是账本口吻），
说的永远是「现在是几份」。

### 三条不说

| 情形 | 为什么 |
|---|---|
| 落点不是成品（`tasks/` 的留痕、`notes/` 的成文） | 与「你交出 N 份」同一口径；说了就与它自己的账自相矛盾 |
| `更新` / `未变`（同一轮里改存同一份） | 架子上没多一份，复读一句就是假消息 |
| 宠物被关（`pet_enabled=false`） | 走 `emit()` 的既有闸门，这里不另开一条 |

**也不弹通知**：现有会 toast 的四类（失败、问候、到期复习、习惯）都是「不弹就等于没说」的；
成品是好事，页面上的气泡够了（`/api/pet/feed` 本来就在轮询）。前端因此**一行都没改**。

**（2026-09-17 补）** 上面那条台词现在**有几句说法轮着说**（Z3 · PLAN4 §2）：
`task_done` / `task_failed` / `cards_done` / `output` / `mastered` 各备 2–3 句，
轮换键是「这个 kind 之前说过几次」（确定性、零模型、没有随机数）；**第一句永远是从前那句**，
所以不传轮换位的调用方一个字节都没变。两条界线：**里程碑那半句不许轮换**
（「第一份」「这是第 N 份」「连着第二次说通」每句变体里都原样出现），**只换说法不换事实**
（名字 / 数字 / 缺口在每一句里都得拼对，有测试逐句验）。

### 验收

| 层 | 结果 |
|---|---|
| 台词（纯函数） | 3 条：`count=3` → 「第 3 份」、`count=1` → 「第一份」、`count=0` → 只有前半句不编数 |
| 「算不算成品」（纯函数 + 真目录） | 2 条：`deliver/` 开口，`tasks/` 与 `notes/` 一个字都没有；两份成品 → 「第 2 份」（数与成长值读的是同一批目录） |
| 定时任务那条路（真 `_write_vault`） | 2 条：落 `deliver/` → **只有** `output` 一条、没有「跑完了」；落 `tasks/` → 只有「跑完了」 |
| 引擎那条路（真 `report.save`） | 1 条：`research/` 的成品由写盘的人说，`run_task` 不回声（引擎自己落了盘，也没往 `tasks/` 抄第二份） |
| 会话那条路（真 `_save_artifact`） | 3 条：新落一份 → 一句；`compose` → `notes/` 不是成品，闭嘴；同一轮改存（`更新`）不复读 |
| 全量 | 后端 **76 个测试文件全绿**（4.0 分钟，`run_tests_fast.py`），本轮新增 9 条 |
| 前端 | 未改动（气泡渲染的就是 `text`），既有 295 条不受影响 |

## 7. 维度四的取舍：状态机、混合记忆、房间、本地模型

> 2026-09-16。另一份提案（「维度四：技术实现与架构灵感」）。逐条判断记在这里，
> 因为它与环一/环二/环三是同一族东西——`pet_state.py` 与 `pet_room.py` 的文件头
> 本来就标着「维度一 / 维度四」。

**总判断：四条里两条这个仓库已经按「派生而非记账」的形态建好了，一条与两周前刚做完的
导航收缩正面冲突，一条是配置问题被写成了开发问题。**

### 7.1 中心化状态机（XState）——🟡 已有，但形态是派生的

`pet_state.compute()` 就是一个状态机：输入 = 当前页面 + 真实活动（专注计时、上次产出多久前、
离开多久、几点），输出 `mode` → `MODE_ACTION` → 九个姿势；「任务状态变 → 宠物跟着变」
已经在里面（`celebrating`＝刚交出成品、`busy`＝有活在跑、`pupil`＝你正在讲）。前端只做一次
仲裁：`flash ?? (thinking ? 'review' : state.action)`。

**不换 XState**：真值在 SQLite（`task_runs` / `tutor_sessions` / `pet_events`），客户端那台
机器只能是**第二份真值**。这个仓库为「两份真值」付过四次账（`turn_trace.flags`、saveHint、
路由结论、小屋架子 vs 工作页清单），每次都是「查询是对的、答案是错的」。XState 的价值在
**客户端拥有真值**的多步流程，这里没有那种东西。同理：**不引前端状态库**（现在依赖只有
react / react-router / markdown 三样，「刷新即真值」正是它简单的原因）。

### 7.2 混合记忆——✅ 长期已有 / ⛔ Redis、Milvus 不做

| 提案 | 仓库现状 | 判断 |
|---|---|---|
| 长期记忆进向量库 | Chroma 已接（`indexer` / `retriever` / `embedder` / `reranker`）+ `memory.py` + `beliefs` / `kg` | ✅ 已有 |
| 短期记忆进 Redis | 短期 = `messages` + `compaction.py` + `inflight.py` | ⛔ **不做** |
| 画像 / 进化史进向量库 | 画像是**算出来的**（W7）；成长是累计计数；屋里的东西标「到手那天」 | ⛔ **方向相反** |

- Redis 的代价是**负的**：本地优先 = 单用户、单进程。现在查一次是进程内的一次 sqlite 读
  （毫秒级），换 Redis 是「用户自己装一个 Windows 常驻服务 + 一次 TCP 往返」，更慢，还多一个
  会挂的东西。判据与 `pet.notify` 同一条：**不为流程引入第二个必须常驻的进程**。Milvus 同理。
- **最该顶回去的是第三条**：把「你交出 3 份成品」塞进向量库，等于把它降级成「大概三份」。
  可数的东西不要用相似度去近似——这正是 §6 那句台词能说「第 3 份」而不用猜的原因。
- 真觉得不够聪明，缺的不是**存哪**，是**每轮往上下文里塞什么**（`fullctx` / `compaction` /
  `retriever` 的地盘）。

### 7.3 房间当主界面——⛔ 不做；「行为绑定 UI」——🟡 做，见 §8

已经有的：悬浮 `PetWidget`（拖动 / 气泡 / 插件面板）+ `RoomPane` 小屋（`pet_room.py`：
屋里每一件都是算出来的、标的是**到手那天**、没有「还差 N 件解锁」）+ 九张 webp 全被
`pet_state.ACTIONS` 用上。屋里的技能卡现在就能点进 `/work?tab=lab`——**「点书架弹知识库」
这个交互形态已经存在，只是它是列表不是像素画。**

**（2026-09-17 补）屋里多了一类东西：概念卡**（P2 · F13 的后半，实现记录在 PLAN §6.10）。
它是学页那张**学习地图的镜子**：只摆碰过的三档（已掌握 / 在学 / 卡住），点开走既有的
`/tutor?new=<概念>` 深链。「未触及」一档**连读都不读**——那是「还没做的事」的清单，
与上一段「没有『还差 N 件解锁』」是同一条规矩。要注意它与别的屋中物**不是一类**：
徽章/摆设/技能卡是到手就不再变的，概念卡照的是此刻，状态会来回动。

**不做主界面**：`Layout.tsx` 上原写着「导航五区（2026-09-13 收缩）：一眼能数完，每区一件事」
（**2026-09-18 改版**：侧栏换成了可展开的分组——五区还在，只是每区下面能展开出它的子功能；
「不做像素桌子」这条结论不受影响，理由还是下面这两条）。
把工作面塞进像素桌子上的一次点击，是把那次教训反着再走一遍——**菜单变寻宝**。美术成本也是
真的：现有资产只有 9 张**角色**图，屋子一件美术都没有（tilemap、碰撞、走位、交互热区全要新做）。

## 8. 做掉的三件：姿势接真信号、事件流、屋里那件东西

排的是性价比：① 行为→姿势/台词（小、感知最强）② 一条 SSE 替掉轮询 ③ 屋子继续做深。
**Ollama 那一格按你的话不接**（它本来就是配置级，不是开发项）。

### 8.1 ① 姿势与台词接到真信号上

补的两样都是 `task_runs` **看不到**的东西：

| 信号 | 从哪来 | 之前的问题 |
|---|---|---|
| 有活正在跑（还能说清在跑什么） | `inflight.running()`（进程内）+ 引擎名的中文标签 | 只有「今天有 `task_runs` 行在跑」——**页面点出来的六个引擎一行都不写**，而那正是你盯着转圈的那几秒 |
| 有一步停着等你点头 | `task_runs.status = _GATE_STATUS`（引用 `tasks` 那一份常量，不抄） | 状态机里根本没有这一档：工作链停着，宠物照旧显示「陪你干活」 |

台词也跟着具体了：`复盘正在跑，我去盯着。`（认不出引擎名就退回「活正在跑，我去盯着。」）、
`有一步停着，等你点头。`。**卡点那句不报件数**——一报就成了「你还欠 N 件」的口吻，那是这个
仓库封存过的机制；仓库本来就会为卡点弹一条桌面通知（`tasks._notify_gate`），这里只是把同一件
事实摆到它脸上。它与既有的「提醒」（`gatherNudges`，带「去放行」按钮、一天只念一遍）分工明确：
**提醒是一次的事件，姿势是持续的现状。**

顺带删掉了 `_signals` 里那个 `stuck_open`：它采集了却从来没人读（卡点数是催办口吻，不该进台词）。

### 8.2 ② 一条 SSE 事件流，轮询退成兜底

`GET /api/pet/stream`（`routers/pet.py`）只送两样东西：

1. `event` —— 新台词，**就是 `/feed` 会给的那几行**（同一条路，不是第二份真值），
   按说出口的顺序发；
2. `work` —— 「此刻在跑什么」变了的指纹（`pet_state.work_fingerprint()`：进程内引擎 +
   今天的在跑/卡点计数），变了才发。

**状态不由这条流算**：它取决于你在哪个页面、多久没动键鼠，那是浏览器才知道的事
（`idle_sec` 从来只活在浏览器里）。所以流只说「有新东西了」，算还是 `/state` 算。

前端（`stream.ts` 的 `streamPet` + `PetWidget`）：流接上 → 台词即时冒泡、姿势即时重算，
那条 15 秒的 feed 轮询**停掉**；流断了 → 退避重连（5→10→20→30 秒封顶），**这期间轮询照旧跑**。
这条兜底是刻意的：流挂了的最大风险不是慢，是**静默**——页面一切正常，只是它再也不说话。
新台词是 `output` / `mastered` 时，顺带重看一眼慢的那几样（架子、EXP、最近搞懂）。

### 8.3 ③ 屋子做深：从「会自动动」到「看得见它在动」

`pet_room` 的架子读的就是 `pet.is_output_path` 那批文件（产出落盘 → 架上多一件，**宠物不需要
被通知**），`pet_state` 的 `celebrating` 窗口（10 分钟）给的姿势就是 `jumping`，缺的只是
「一句话」——那是 §6 刚补的 `output` 台词。这一轮把**剩下的三处接缝**补上了：

| 接缝 | 之前 | 现在 |
|---|---|---|
| 屋里那只零柒的姿势 | 写死的 `/pet/idle.webp`——它明明在跑、在跳，屋里永远站着不动 | 读**同一个** `/api/pet/state`：`jumping` 就是跳，`running-right` 就是在盯活，`waiting` 就是在等你点头；台词也照它的（空着就不画） |
| 架上「哪一件是刚到的」 | 每行只有日期，看不出哪份是刚交出去的 | 24 小时内的说「2 分钟前」并高亮；**它叼着的那份**当场标「它刚叼回来的」 |
| 你正看着这一页时 | 只在这一页挂载时取一次——后台落了一份成品，架上不会多 | 每 15 秒重取一次（这一页只在你看着它时挂着，切进来本来就重取；为省这 15 秒再开一条 SSE 不值得） |

「它叼着的那份」不能让界面自己再算一遍「谁最新」——那是第二份判定，两处迟早各指一件东西。
所以 `pet_room.carried()` 多给一个 `ref`（就是架上那一行的 `path`），界面只做一次字符串相等。
门槛那件（徽章 / 摆设）**没有**这个字段：它本来就不在架上。

顺带把九个姿势的清单与那道「不认识的姿势退回 idle」的闸从 `PetWidget` 搬进 `petFace.ts`：
小屋现在也画同一只宠物，两边各留一份清单**迟早分叉，而症状是一张破图——静默的那种**。

### 验收

| 层 | 结果 |
|---|---|
| 优先级（纯函数） | `gated` 赢 `busy`（需要你的那件先说）、输给 `celebrating`；`gated=0` 不算卡点 |
| 卡点那句 | 不报件数：`gated=1` 与 `gated=3` 是同一句话 |

## 9. 把「又卡住」摆进界面

判据与那句话是 §3 做掉的（`tutor.is_recurring_mistake` + 宠物那句台词）。缺的只是**看得见**：
台词落在一张会滚动的流里，飘过去就没了。这一格把它摆到学习页上——**没有新接口、没有新真值**：
`GET /api/tutor/recurring`（§3 就有了）喂两处标。

### 摆在哪儿，以及为什么不另起一栏

§7 里那句「从那个派生视图上加，别另起一份」就是这里的做法：这个信号本来就是「卡住」那一档里
**更窄的一批**（接住过卡在哪、最近一次还是半懂、还在近 7 天），另起一栏等于把同一批概念摆两遍。
所以它是**一个标**，出现在两个"扫过去会看到它"的地方：

| 位置 | 为什么 |
|---|---|
| 学习地图里那条概念行（「卡住」档） | 那一档就是它的母集；标上去 = 「这一批是又一次没过去的」 |
| 「待解的卡点」清单那一行 | 你在这里动手（✓ 关掉它 / 点开重学）——扫这一列时不该看漏 |

标是 `RepeatChip`（`TutorPage.tsx` 导出，单独可测），title 写的是**事实**：接住过你卡在哪几次
（`recalled`）。**不是计数、不是待办、不是「还欠几次」**——这与 §3 那条「不设队列、不计数、
不催」是同一条规矩，只是换了张皮。

### 一条硬约束：界面上的标与它嘴里的话**必须是同一批**

判据只有后端一处（`is_recurring_mistake`），前端只做一次 `Map` 查找，**绝不重算**
「算不算又卡住」——两份实现分叉的那天，你会看到界面上标着、它却不说，或者反过来。
所以整页测试里钉的就是这个：同一份 `recurring` 数据喂进去，标只落在那一批概念上（两处各一次），
别的概念照旧摆着但没有标。

`RepeatChip` 收**整行**而不是一个布尔：title 里的次数是这一行的事实（`recalled`），
拿不到就不该编一个 0 出来——第一版正是那么写的（给卡点清单那处传了个 `recalled: 0` 的假行），
写完当场改掉。

### 验收

| 层 | 结果 |
|---|---|
| `RepeatChip`（纯组件） | 画「又卡住」+ title 里是**真数出来的**「接住过你卡在哪 2 次」；传 null 就一个字不画 |
| 整页接线（真渲染 TutorPage） | 打开「记录」档：标只落在「又卡住」那条概念上、**地图与卡点清单两处各一个**；另一条概念照旧摆着但不带标；一个都没有时一个空标都不摆 |
| 后端路由 | `/api/tutor/recurring` 在 `app.openapi()` 的路径表里（直接调函数验不出注册这一层），且它给的就是**同一批判据**的结果 |
| 全量 | 后端 **76 个测试文件全绿**（4.1 分钟）；前端 **29 个文件 312 条全绿** |
